# SHIELD Prototype

## Setup

- Unity: **6000.3.4f1 LTS**
- Rendering: Built-in Render Pipeline, 2D; SOLO locks portrait and DUO locks the orientation active when the run starts
- Input: legacy `UnityEngine.Input`
- Required dependency: DOTween (installed under `Assets/Plugins/Demigiant`)

Run **Tools > SHIELD > Build Prototype** after a fresh checkout or whenever generated scenes/prefabs need rebuilding. The tool preserves existing configuration assets, warns before replacing generated scenes, configures Built-in/legacy-input settings, and places `Home`, `Game`, then `DuoGame` in Build Settings.

Open `Assets/SHIELD/Scenes/Home.unity` and press Play. The Home scene is build index 0.

## Controls

- Mobile: begin one touch anywhere outside UI to rotate clockwise by 90 degrees.
- Keyboard: either `Left Arrow` or `Right Arrow` performs the same gameplay tap; both follow the current normal/reversed rotation direction.
- Editor/development: `Space` performs the same gameplay tap.
- UI: Pause, Resume, Restart, and Home consume their touches and never rotate the shield.

DUO controls:

- Mobile: a touch in the top/left half rotates that arena; a touch in the bottom/right half rotates the other. Multi-touch can rotate both in the same frame.
- Keyboard: `Left Arrow` controls the left or upper arena; `Right Arrow` controls the right or lower arena.
- `Space` is disabled. Pause, Resume, Restart, and Home apply to the combined run.

Debug controls are available in the Editor/development builds:

- `R`: restart
- `I`: toggle invincibility
- `1` / `2` / `3` / `4`: force the pending projectile to Top / Right / Bottom / Left
- `5` / `6` / `7` / `8` / `9` / `0`: force the pending projectile type to Yellow / Green / Blue / Purple / Red / Orange
- `[` / `]`: jump through representative scores 0, 50, 100, 200, 500, 1000
- `F1`: toggle the debug overlay

Debug score injection never writes the stored best score.

## Tuning and assets

- Difficulty milestones, warmup, jitter, history filtering, and authored fragments: `Assets/SHIELD/ScriptableObjects/DifficultyConfig.asset`
- Shield tween duration, initial delay, pool size, and normalized visual dimensions: `Assets/SHIELD/ScriptableObjects/GameplayConfig.asset`
- Projectile type rarity, eight-attack Yellow warmup, speed multipliers, and effect durations: `Assets/SHIELD/ScriptableObjects/GameplayConfig.asset`
- Colors, VFX values, milestone feedback, and optional audio clips: `Assets/SHIELD/ScriptableObjects/FeedbackConfig.asset`
- SOLO best, DUO best, and preferences use separate versioned `PlayerPrefs` keys through `PlayerPrefsPersistenceService`.

The placeholder circle/square art, prefabs, material, scenes, and font asset are generated by the builder and can be replaced without changing gameplay logic. Audio fields are optional and null-safe.

The active score is centered inside the core, rendered as black overlay text above the world-space core visual, and auto-sized from the configured core diameter so three-digit values and their milestone pulse remain contained.

## Projectile types

- **Yellow (92%)**: standard projectile. Blocking awards one point; reaching the core is lethal unless Green protection is active.
- **Green (2%)**: travels at twice the current standard speed. Blocking awards one point and grants ten seconds of protection from every core hit except Red. Letting it reach the core is safe but awards no score and grants no protection.
- **Blue (2%)**: travels at twice the current standard speed, like Green. Blocking awards one point, slows projectiles already in flight to 50% speed for 1.5 seconds, and pauses new spawns for the same duration. Letting it reach the core is safe but awards no score and activates no effect. The pending spawn countdown resumes afterward at regular speed without a catch-up burst.
- **Purple (2%)**: blocking destroys it and awards one point without an effect. Letting it reach the core is safe, awards no score, and reverses tap rotation for five seconds.
- **Red (1%)**: behaves like Yellow but always kills on a core hit, including during Green protection.
- **Orange (1%, “The Faker”)**: its true attack direction is chosen normally, but it appears from the opposite side. Its straight approaches move at exactly Yellow's current world speed. Well before fake-side shield contact it performs a 0.5-second clockwise curve at the configurable `orangeSwitchRadiusNormalized`, then leaves a readable straight approach toward its true-side shield. Orange therefore reaches the core one switch-duration later than Yellow. Only the true side can block it. Blocking awards one point; missing is lethal unless Green protection is active.

The first eight projectiles of every run are Yellow. Green, Blue, and Purple timers coexist, refresh rather than stack, freeze while paused, and appear compactly near the upper edge of the HUD. Core color priority is Green, then Purple, then Blue, then the white base color.

## DUO mode

DUO runs two complete arena simulations at once. Wide and square screens place them left/right; tall screens place them top/bottom. The starting arrangement is locked for the run. Each arena owns its score, score-driven difficulty, attack history, projectile pool, eight-Yellow warmup, and Green/Blue/Purple effects. A Blue slowdown or Purple reversal on one board never affects the other.

Both boards begin simultaneously. After the opening pair, a configurable `duoCrossArenaImpactGap` (default `0.10s`) prevents near-simultaneous planned impacts across boards without changing either board's SOLO tuning. Either core dying ends the combined run. The results screen reports P1, P2, their total, and the separately persisted DUO best score; only the struck core plays the destruction animation.

## Architecture guarantees

`InputManager` is the only custom SHIELD script with `Update()`. It applies input before calling the central gameplay tick. No custom script uses `LateUpdate()` or `FixedUpdate()`. Projectile impacts use normalized travel progress plus logical direction. Travel durations and impact gaps are time-based rather than pixel- or world-distance-based, keeping reaction time consistent across resolutions. Screen, safe-area, camera-size, and aspect changes trigger an arena reflow; active projectiles retain their normalized progress, remaining travel time, and committed shield-contact state while their visual paths resize. A matching projectile is removed at the rendered shield radius; one that has already passed a mismatched shield continues to the core perimeter, disappears on contact, and cannot be caught late. Only shield blocks increase score. Shield-block bursts retain their existing animation while inheriting the blocked projectile's color. Orange keeps its true direction as gameplay authority while its opposite-side opening and clockwise orbit remain visual path phases. Blue slowdown scales normalized progress so projectiles already in flight react immediately, while the spawner freezes its pending countdown until Blue expires. A lethal miss triggers the core destruction presentation. Colliders, rigidbodies, transform overlap, and visible shield tween position are never gameplay authority.

Run **Tools > SHIELD > Validate Prototype** for automated structure, configuration, build-order, no-physics, missing-script, two-arena, and single-Update checks. Batch smoke coverage is available for both `ShieldPlayModeSmokeTest.RunBatch` (SOLO) and `ShieldDuoPlayModeSmokeTest.RunBatch` (DUO).
